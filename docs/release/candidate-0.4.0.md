# Candidate 0.4.0 — explicit folder-access control

This local, unpublished candidate implements the approved [Figma panel](https://www.figma.com/design/af5pH0tpFiZo83tYlEUywB?node-id=30-101). The panel remains 360×152 at its normal width: two equal Stop/Reload buttons plus a 64×64 folder control. Red means no usable folder grant; green means a folder is approved. Hover/focus describes the state and approved folder name without an absolute path. The local Figma SVG remains 24×24.

A human can explicitly select or replace a media folder. Cancelling or failing selection keeps the old folder/token; it does not hide the normal bridge status. Pending selection is disabled against repeated activation. Selection cannot begin during an active host command; new file work during replacement rejects with FILE_ACCESS_PENDING before file access. Stop, reload and explicit forgetting invalidate stale picker/token results; ordinary lifecycle and same-ID updates preserve the remembered grant. Existing Entry and request-bound Node authorization remain mandatory.

The source package, manifest and protocol identify 0.4.0. Plugin ID, token key and manifest permissions are unchanged. The reviewed CCX adds assets/folder.svg as an eighth allowlisted file; no temporary Figma URLs, proprietary packaging tooling or owner data belong in its payload. Public 0.3.12 and its update feed are unchanged until a separate publication. --release must fail for this unpublished candidate; use npm run onboard -- --ccx REVIEWED_CCX --sha256 TRUSTED_REVIEW_HASH for local validation, adding --install only for an authorized installation.

All 204 local tests pass with no failures or skips. A separate actual previous-release 0.3.12 bundle restores its saved approval into 0.4.0 fixtures without another picker and passes Entry/Node file validation. Headless browser checks at 320/360px confirm the Figma geometry, colors, loaded local SVG, keyboard activation and cancellation/failure retention. Dependency review reports zero known vulnerabilities. These bundled-runtime, IPC/broker and browser checks are separate from native Adobe behavior. No native folder selection, 0.4.0 runtime activation or Windows validation is claimed by this report. Native Developer Mode/activation and tooltip/SVG rendering require a separate actual-host observation. Source changes do not restart/save Premiere or imply a successful new runtime. Windows remains experimental.

Adobe's [filesystem recipe](https://developer.adobe.com/premiere-pro/uxp/resources/recipes/filesystem-operations/) documents picker approval and persistent tokens at the 25.6 baseline; [manifest documentation](https://developer.adobe.com/premiere-pro/uxp/plugins/concepts/manifest/) documents SVG support. These references establish intended API/asset usage, not actual runtime proof.
